# 界面设计规范

酒馆界面由三方共同组成：DSH 宿主、本插件、第三方插件（以及人物卡自带的 HTML）。设计时先分清每块区域归谁，只改本插件画的部分；宿主和扩展点只调外框、间距和尺寸。

## 流程

1. 截原图：用真实运行的应用截当前界面，桌面 1440×900，手机 390×844，内容状态（同一局、同一个标签页）前后一致。
2. 出稿：在 Design 画布里每行左边「原来」、右边「修改后」，旁边便签逐条写改了什么。影响多个界面时先画一张样板，确认后再画其余。
3. 动态状态也要画：同一界面在不同状态下长得不一样时（例如输入框上方的面板），每个关键状态各一组对比。
4. 写代码、开 PR、审核、合并、删分支，见 `AGENTS.md`「界面改动」。

## 颜色与主题

- 只用主题变量：`--dsh-tavern-accent`、`--dsh-tavern-accent-soft`、`--dsh-tavern-accent-border` 和宿主的 `--dsw-alias-*`、`--dsw-specific-*`。不写死色值；设计稿里的颜色只是默认主题下的示意值。
- 允许的固定值仅限兜底（`var(--dsw-alias-brand-text, #fff)`）和压暗强调色这类混色（`color-mix(in srgb, var(--dsh-tavern-accent) 88%, #000)`）。
- 宿主自己的控件（发送按钮、输入框等）保留宿主配色，不改成强调色。
- 每次改动都要在浅色和暗色、默认主题和至少一个其他主题下检查。

## 按钮层级

- 一个区域最多一个主按钮：实心强调色（`.dsh-tavern-btn.primary`）。
- 普通操作：描边按钮，悬停时描边和底色变强调色。
- 关闭、收起这类退出操作：无边框的文字或图标按钮。
- 会丢数据的操作（放弃开局、回退、删除）：警示色文字按钮，放在远离主按钮的一侧。

## 动态区域

下面这些区域在运行时由宿主或插件填充，数量、顺序、高度都会变。设计时只定外框和间距，不能写死里面的内容：

| 区域 | 谁填充 | 设计要求 |
|---|---|---|
| 顶栏工具位 `conversation.session.header.utilities` | 宿主 + 插件按 order 插入 | 按钮个数不定，放不下时要能收起 |
| 视图标签 `conversation.view` | 宿主（Chat、Trajectory）+ 插件（完整上下文、画廊等） | 不删减，窄屏横向滑动 |
| 输入框上方操作栏 `conversation.input.dock` | 内置按钮 + `registerComposerAction` | 窄屏单行滑动或收进「更多」 |
| 操作栏下的面板 | 重新生成意见、候选项、编辑正文、提问，按状态替换 | 贴在输入框上沿，高度随内容变 |
| 每轮回合信息行 | 宿主 + `registerMessageAction` | 右侧给插件按钮留位置 |
| 变量回执 | 本插件，随结算状态变 | 状态文字长度不定 |
| 右侧栏标签 | dsh-better-sidebar，按需打开、可关闭、＋ 新增，含 `registerPanel` | 不改成固定切换 |
| 人物卡列表 | 内置列表 / 宫格 + `registerCardListView` | 视图切换按钮个数不定，列表区整块可被替换 |
| 状态栏、开场白预览 | 人物卡自带 HTML | 高度不定，容器内部滚动 |
| Guide、人物档案、游玩历史 | 随数据增长 | 面板整体滚动，空状态要有说明 |

插件接口的完整说明见 `docs/plugin-api.md`。

## 布局

- 正文是主任务：桌面正文限宽约 700px 居中，侧栏不能比正文宽。
- 弹窗高度固定、内容区内部滚动，搜索和切换时不跳动。
- 手机：正文满宽，左右 20px 边距；侧栏用盖在上面的抽屉加遮罩，不挤压主界面；点按区域至少 36px，主要操作 44px；输入框字号不小于 16px，避免 iOS 自动放大。
